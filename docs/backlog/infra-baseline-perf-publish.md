## Current state (2026-06-17)

The infrastructure pieces of this ticket already shipped alongside [[core-perf-gate-harness]]:

- Per-tier baselines live under `tools/perfgate/baselines/{low,mid,high}/<metric>.json`.
- `tools/perfgate/regen-baselines.dart` reproducibly regenerates them from a bench log, and refuses to overwrite an existing file without `--force --justification "<reason>"` — every promotion writes a sibling `<metric>.justification.md` that reviewers can diff in the PR.

What remains is **content**, not infrastructure: the seeded PLAN.md §6 ceilings need to be replaced with measured values from the LOW reference device. That is exactly Step 1–2 of `tools/perfgate/PROMOTION_CHECKLIST.md`. MID/HIGH are gated indefinitely on `infra-device-runner-matrix` (P3).

This file closes out the same time `core-perf-gate-harness` does — they share the LOW promotion gate.

## Problem
Perf baselines exist locally during a sprint but aren't published anywhere durable. Each new sprint re-discovers them.

## Scope
- Commit per-tier perf baselines as JSON under `tools/perfgate/baselines/<device>/<scenario>.json`.
- A short script regenerates baselines from a known-good run and writes the same files.
- Reviewers can diff in PRs.

## Out of scope
- A hosted dashboard (defer until retailer asks).

## Acceptance
- [ ] Baselines reproducibly regenerated by the script.
- [ ] PRs that move a baseline must include the JSON diff and a justification line.

## Dependencies
